# XM Trading – المرحلة السادسة (بنية اختبار آمنة)

هذه حزمة هندسية تجريبية قابلة للتطوير، وليست منصة مالية إنتاجية أو تطبيقًا معتمدًا من XM.
لا توجد مفاتيح مزودين حقيقية، ولا يتم إرسال OTP فعليًا، ولا يوجد فحص هوية حقيقي أو تداول/إيداع/سحب.

## تشغيل قاعدة البيانات والخادم
يتطلب Docker:
```bash
docker compose up --build
```
API: http://localhost:8000
توثيق API: http://localhost:8000/docs
قاعدة PostgreSQL: localhost:5432 (قاعدة trading_demo)

## المصادقة
- تخزين كلمات المرور باستخدام Argon2.
- رموز JWT قصيرة العمر.
- OTP تجريبي عبر سجل الخادم فقط عند `APP_ENV=development`.
- في الإنتاج يجب ربط مزود OTP معتمد، تفعيل rate limiting، TLS، إدارة الأسرار، تدوير المفاتيح، وسياسات قفل الحساب.

## KYC والتكاملات
يوجد adapter interface فقط. لا يرسل بيانات هوية لأي جهة ولا يصدر قرار KYC.
لا تضع بيانات حقيقية أو وثائق هوية في هذه البيئة.
اربط مزود KYC/OTP/وسيط/مدفوعات فقط بعد عقد وموافقة وتحقق امتثال من المزود والجهة القانونية.

## Android
يوجد مشروع Android WebView wrapper مبدئي. افتح مجلد `android` في Android Studio ثم Sync/Build.
لا يمكن وصف APK/AAB بأنه مبني أو مختبر من هذه الحزمة؛ يلزم Android SDK/Gradle وبيئة توقيع خاصة بك. لا تضع مفاتيح التوقيع في المستودع.

## تشغيل الاختبارات
```bash
cd backend
pip install -r requirements.txt
pytest -q
```

## متطلبات ما قبل الإنتاج
1. إثبات التفويض وحقوق استخدام العلامة ونطاق التطبيق.
2. رأي قانوني وترخيص مناسب لكل بلد/خدمة.
3. مزود OTP وKYC ومدفوعات/وساطة معتمد بعقود ومفاتيح سرية.
4. اختبار اختراق مستقل، مراجعة خصوصية، مراقبة وتنبيه ونسخ احتياطية.
5. إكمال تدفقات KYC/AML وعمليات دفتر الأستاذ ومصالحة الأموال.

## تحديث أمني للمرحلة 6
- تم استبدال إنشاء الجداول التلقائي بترحيلات Alembic؛ يشغّل الحاوي الترحيلات قبل تشغيل API.
- يجب نسخ `.env.example` إلى `.env` وتوليد كلمات مرور ومفاتيح عشوائية فريدة. لا ترفع ملف `.env` إلى Git.
- في وضع الإنتاج يرفض الخادم التشغيل دون JWT_SECRET وOTP_PEPPER بطول 32 بايت على الأقل، ويرفض SQLite.
- OTP في هذه الحزمة تطويري فقط ولا يرسل رسائل فعلية. لا تفعّل الإنتاج قبل ربط مزود OTP معتمد واختبار التسليم.
- OTP أحادي الاستخدام، بمهلة انتهاء، وتُبطل الرموز السابقة، وتُحد محاولات التخمين إلى خمس محاولات.
- شغّل `docker compose up --build` بعد إعداد `.env`. لا تعرض منافذ قاعدة البيانات أو API للعامة قبل إعداد TLS وجدار حماية ووكيل عكسي.
- هذه الحزمة لا تزال ليست نظامًا ماليًا إنتاجيًا: لا توجد بعد إدارة جلسات/Refresh Tokens وإبطالها، ولا تحديد معدل موزع عبر Redis، ولا مزود KYC/AML فعلي، ولا دفتر أستاذ مزدوج.

## تقوية الخادم – المرحلة 8
- تمت إضافة محدد محاولات ثابت النافذة مخزن في PostgreSQL/SQLite، ويشارك العدادات بين عمال API الذين يستخدمون قاعدة البيانات نفسها.
- حدود التسجيل: 5 طلبات لكل عنوان IP في الساعة.
- طلب OTP: 10 طلبات لكل IP و5 لكل بريد خلال 15 دقيقة.
- التحقق من OTP: 20 طلباً لكل IP و10 لكل بريد خلال 15 دقيقة، بالإضافة إلى حد المحاولات داخل رمز OTP نفسه.
- تمت إضافة رؤوس حماية HTTP، بما فيها منع التخزين المؤقت، وHSTS في وضع الإنتاج.
- أضيف ترحيل Alembic رقم 0002 وجدول اختبارات مستقل.

**قيود لم تُحل ولا يجوز تجاوزها في الإنتاج:** إرسال OTP الفعلي، مزود KYC، جلسات/إبطال الأجهزة، سلسلة تدقيق غير قابلة للعبث، دفتر الأستاذ المالي المزدوج، مزود التداول والأسعار، الدفع والسحب، اختبارات اختراق واستعادة النسخ الاحتياطية. لا تُجمع أموال ولا تُرفع مستندات هوية حتى اعتماد المزودين والتراخيص والعقود. ما زال APK/AAB غير مبني أو موقع.
